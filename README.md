# Monte Carlo Simulation: Will the Bake Sale Make Money?

This is an end-to-end, dependency-free Python demonstration of the bake-sale example from the video. It turns uncertainty about attendance, buying behavior, and customer spending into 10,000 possible event outcomes, then measures how often the event earns a profit.

## The business question

You must spend **$250 before the event**. You do not know exactly how many people will attend, how many will buy, or how much buyers will spend. The question is:

> What is the probability that revenue will exceed the $250 fixed cost?

## Assumptions

| Input | Distribution used in each trial | Meaning |
|---|---:|---|
| Attendance | Random integer from 80 to 180 | Number of visitors |
| Purchase rate | Uniform from 30% to 70% | Each visitor's probability of buying |
| Average purchase | Uniform from $3 to $8 | Revenue per customer in that trial |
| Fixed cost | $250 | Paid regardless of sales |
| Trials | 10,000 | Number of possible bake sales |

Uniform distributions are used because the video supplies ranges but no evidence favoring values within those ranges.

## How one trial works

1. Randomly choose attendance, purchase rate, and purchase amount.
2. Walk through every attendee and independently decide whether they buy.
3. Count the customers.
4. Calculate `revenue = customers × purchase amount`.
5. Calculate `profit = revenue − $250`.
6. Store the outcome as one row of data.

The program repeats this process 10,000 times. This produces a distribution of possible profits instead of pretending there is one certain forecast.

```text
Ranges and fixed cost
        ↓
Sample one possible event
        ↓
Simulate each visitor's purchase decision
        ↓
Revenue = customers × purchase amount
        ↓
Profit = revenue − fixed cost
        ↓
Repeat 10,000 times → summarize → visualize
```

## Run the complete example

Python 3.10 or newer is recommended. There are no third-party dependencies.

```bash
cd ~/Downloads/code/montecarla/bake-sale-monte-carlo
python3 run.py
```

To use more trials or a different reproducible random sequence:

```bash
python3 run.py --trials 50000 --seed 7 --output-dir output
```

The seed defaults to `42`, so repeated runs produce the same result.

## Results for seed 42

| Metric | Result |
|---|---:|
| Trials | 10,000 |
| Chance of profit | **71.9%** |
| Average profit | **$104.51** |
| Median profit | **$77.25** |
| Middle 90% of outcomes | **-$102.55 to $404.74** |
| Worst simulated result | **-$195.57** |
| Best simulated result | **$813.11** |

The model says the bake sale is more likely than not to be profitable, but it does not guarantee success. About 28.1% of these simulated events fail to produce a profit. Also notice that the average is higher than the median: a smaller number of very successful events pull the average upward.

## Generated data

The video does not use a downloaded real-world dataset. Its data is generated by the simulation. Running `run.py` creates:

- `output/simulation_results.csv` — 10,000 trial-level records plus a header.
- `output/profit_histogram.svg` — chart of the complete profit distribution.

CSV columns:

| Column | Description |
|---|---|
| `attendance` | Visitors sampled for the trial |
| `purchase_rate` | Buying probability sampled for the trial |
| `customers` | Simulated number of buyers |
| `purchase_amount` | Spend per customer sampled for the trial |
| `revenue` | Customers multiplied by purchase amount |
| `profit` | Revenue minus the $250 fixed cost |

Open [`index.html`](index.html) for a presentation-friendly walkthrough, or open `output/profit_histogram.svg` directly for the chart.

## Code map

- `simulation.py` contains assumptions, trial simulation, percentiles, and summary statistics.
- `run.py` is the command-line entry point and generates CSV and SVG files.
- `test_simulation.py` checks reproducibility, constraints, calculations, and validation.
- `index.html` explains the entire example visually.

## What this model does not know

The result is only as good as its assumptions. Real attendance and spending may not be uniformly distributed. Weather, location, pricing, product availability, and the relationship between attendance and buying behavior are not represented. With historical data, replace these simple ranges with fitted distributions and correlations.
